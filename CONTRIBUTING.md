# Contribution Guidelines

Thank you for your help. This list must stay useful, fair, and accurate.

## What to add

Add a resource only if it helps people search, analyze, or understand video. Good examples are APIs, open models, libraries, datasets, benchmarks, MCP servers, and survey papers.

Do not add these:

- Projects that do not exist yet or that you cannot verify.
- Projects with no documentation or no code.
- Archived or abandoned projects, unless they are still a common reference.
- Duplicates of an entry that is already in the list.
- Video generation tools, unless they also understand video.

## How to add an entry

1. Find the correct section.
2. Add the entry in alphabetical order.
3. Use this format:

   ```markdown
   - [Name](https://link) - Short description.
   ```

4. Make sure that the link returns HTTP 200.
5. Open one pull request for each entry.

## Rules for links

- Link to the official repository or the official documentation.
- Do not use URL shorteners, tracking parameters, or affiliate links.

## Rules for descriptions

- Start with a capital letter and end with a period.
- Keep it short. One sentence is enough.
- Say what the resource does. Do not start with "A" or "An".
- Use facts. Do not use marketing words such as "best", "leading", or "revolutionary".
- Do not compare the resource with other entries.

## Commercial products

Commercial products are welcome. Describe them with the same neutral tone as open source entries. If a product is in beta or private beta, say so in the description.

## Updates and removals

If a link breaks, or a project changes its name or status, open a pull request or an issue. Include a link that shows the change.
